我已经同时使用多设备很久了，自己的笔记本、服务器、NAS，公司的服务器。所有都是SSH客户端登陆。说实话，手动登上服务器，敲一堆命令去做清理、维护、排查这种事，还是挺繁琐的。

之前为了偷懒，我已经在用 [opencode](https://opencode.ai/) 来直接去目标机器上做清理和维护工作。能用肯定是能用的，但实操起来有个绕不开的麻烦：**你得先在那台机器上把 opencode 装好**。装的时候要总处理环境、依赖、Key，如果还要在容器内也进行操作，就更是麻烦了。

所以我很早就关注到了 Wrap 那样的内置 AI 的 SSH 工具。可是我有不想为了这么个工具多掏一份钱。所以，最终找到了 [Netcatty](https://github.com/binaricat/Netcatty)。

<!-- more -->

## Netcatty 是什么

Netcatty 是一个 **内置 AI 的、完全开源的 SSH/SFTP 客户端**，支持 macOS、Windows 和 Linux 三个平台。它本身是个功能齐全的 SSH 工作空间，常见的需求基本都覆盖到了：

- **SFTP 双窗格浏览**，还带了内置编辑器，可以直接在客户端里改远端文件
- **分屏终端 + 标签页 + 会话管理**，多台服务器可以并排着一起操作
- **Vault 视图**，用网格、列表或树形来管理主机，支持快速搜索
- **自定义主题和关键词高亮**，看着顺眼，调试输出也直观

也就是说，即使不看它的 AI 功能，Netcatty 也算是一个合格的现代 SSH 客户端。

## 内置和自定义 Agent 支持

当然，Netcatty 最重要的部分，还是内置 AI 了。Netcatty 内置了一个叫 Catty Agent 的 AI 助手，它能直接读取 ssh 连接后终端的输出，因此它能理解服务器环境、执行命令，还能跨多台主机协调任务——比如你问它"检查一下这台机器的负载"，它会自动跑合适的命令、分析输出、给你一个清晰的结论，而不是让你自己去敲 `top` 再人肉解读。

除了内置的 Agent，它还支持 **自定义 agent**。这一点对很多人都很重要，因为大部分人多半已经有自己习惯用的 agent 了（Claude Code，Codex等等）。能接入自己熟悉的那一套，而不是被限定在又 Agent 上，显然是加分项。

## 核心优势

显而易见，优势就是 **agent 不需要装到目标机器上。** 这类客户端自己建立 SSH 连接，直接通过 SSH 读取远程终端的信息，而 agent 本身还是跑在本地。也就是说，我在本地这台机器上配好的环境、模型、工作流，都能直接用，但处理的对象是千里之外的服务器。省掉了在每台目标机器上反复装环境、调依赖的麻烦。

对我这种"要使用多台机器"的人来说，这个区别是实打实的省事。以前要重复十次八次的安装配置流程，现在一次都不用了。

## 一点感慨

最后说点题外话。Netcatty 当然不是第一个内置 AI 的 SSH 客户端（Wrap事是不是第一个我也不知道），但在目前**完全开源**的方案里，它看起来是相对完善的那个——功能、跨平台、AI 集成度都做得很完整。这也让我越来越感觉到，很多用了十几年的老工具，一旦跟 AI 结合，往往能焕发出意想不到的便利。以前觉得"少了个命令行工具"的痛点，现在往往是一句自然语言加 AI。就能解决的事。

如果你也经常要面对一堆远程服务器，又想省掉"每台机器都要装一遍工具"的麻烦，Netcatty 值得一试。仓库在 [github.com/binaricat/Netcatty](https://github.com/binaricat/Netcatty)，GPL-3.0 协议，感兴趣可以上手，也可以直接去 [netcatty.app](https://netcatty.app) 看看。
