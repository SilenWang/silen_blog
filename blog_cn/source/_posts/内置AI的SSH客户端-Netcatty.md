我平时要维护的服务器不算少，用的又是传统的 SSH 客户端。说实话，手动登上服务器，敲一堆命令去做清理、维护、排查这种事，做多了总会嫌烦。AI 起来之后，我一度幻想能有个工具，让 agent 直接在服务器上干活，我只要在旁边审核结果就行。

之前我也试过用 [opencode](https://opencode.ai/) 直接去目标机器上做清理和维护工作。想法是好的，但实操起来有个绕不开的麻烦：**你得先在那台机器上把 opencode 装好**。装的时候要处理环境、依赖、权限，一趟折腾下来，本来想省事的心情先没了大半。所以那套方案我一直觉得只能算"能用"，谈不上"顺手"。

直到我遇到 [Netcatty](https://github.com/binaricat/Netcatty)，才觉得这类工具终于有点接近我想要的样子了。

<!-- more -->

## Netcatty 是什么

Netcatty 是一个 **内置 AI 的、完全开源的 SSH/SFTP 客户端**，基于 Electron、React 和 xterm.js 构建，支持 macOS、Windows 和 Linux 三个平台。它本身是个功能齐全的 SSH 工作空间，常见的需求基本都覆盖到了：

- **SFTP 双窗格浏览**，还带了内置编辑器，可以直接在客户端里改远端文件
- **分屏终端 + 标签页 + 会话管理**，多台服务器可以并排着一起操作
- **Vault 视图**，用网格、列表或树形来管理主机，支持快速搜索
- **自定义主题和关键词高亮**，看着顺眼，调试输出也直观

也就是说，即使不看它的 AI 功能，Netcatty 也算是一个合格的现代 SSH 客户端，完全能当 PuTTY、Termius 之类的替代品来用。

## 内置和自定义 Agent 支持

真正让我眼前一亮的是它的 AI 部分。Netcatty 内置了一个叫 Catty Agent 的 AI 助手，能理解你的服务器环境、帮你执行命令，还能跨多台主机协调任务——比如你问它"检查一下这台机器的负载"，它会自动跑合适的命令、分析输出、给你一个清晰的结论，而不是让你自己去敲 `top` 再人肉解读。

但其实我觉得更关键的是它支持 **自定义 agent**。这一点对我的使用场景很重要，因为我手上已经有自己习惯用的 agent 工作流了。能接入我自己熟悉的那一套，而不是被绑定在一个内置助手身上，这点在我这里是加分项。

## 它到底解决了什么

回想一下我在用 opencode 直接上服务器维护时的痛点，Netcatty 这类客户端的思路其实很不一样：

**agent 不需要装到目标机器上。** 这类客户端自己建立 SSH 连接，直接通过 SSH 读取远程终端的信息，而 agent 本身还是跑在本地。也就是说，我在本地这台机器上配好的环境、模型、工作流，都能直接用，但处理的对象是千里之外的服务器。省掉了在每台目标机器上反复装环境、调依赖的麻烦。

对我这种"要维护一堆机器"的人来说，这个区别是实打实的省事。以前要重复十次八次的安装配置流程，现在一次都不用了。

## 一点感慨

最后说点题外话。Netcatty 当然不是第一个内置 AI 的 SSH 客户端，但在目前**完全开源**的方案里，它看起来是相对完善的那个——功能、跨平台、AI 集成度都做得很完整。这也让我越来越感觉到，很多用了十几年的老工具，一旦跟 AI 结合，往往能焕发出意想不到的便利。以前觉得"少了个命令行工具"的痛点，现在往往是一句自然语言就能解决的事。

如果你也经常要面对一堆远程服务器，又想省掉"每台机器都要装一遍工具"的麻烦，Netcatty 值得一试。仓库在 [github.com/binaricat/Netcatty](https://github.com/binaricat/Netcatty)，GPL-3.0 协议，感兴趣可以上手，也可以直接去 [netcatty.app](https://netcatty.app) 看看。
